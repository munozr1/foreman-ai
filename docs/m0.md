## Actual bridge configuration

No CLI or configuration-file entry point is distributed. The adapter constructs `src.bridge.config.from_dict(...)`, calls `Bridge.start()`, then runs `Bridge.run()` and stops cleanly on signals.

```python
{
    "fdb": {"api_version": 800, "cluster_file": "/etc/foundationdb/fdb.cluster"},
    "cdc": {
        "stream_name": "foremen",
        "begin_key": b"foremen/",
        "end_key": b"foremen0",
        "cursor_file": "/state/cursor.json",
    },
    "kafka": {"bootstrap_servers": "kafka:9092", "topic": "fdb.cdc.foremen"},
}
```

Raw prefixes work; a directory subspace is not required. If boundaries are passed as strings, the library expects **hex**, not plaintext. Omitting `transactional_id` selects idempotent production. The cursor file is stored in a named volume.

## Actual wire shape

`src.serialization.deserialize_record(payload)` returns a record with `stream_name`, `bridge_timestamp_ns`, and a typed body:

| Body | Fields used |
|---|---|
| `Mutation` | `type`, `param1`, `param2`, `version_index.fdb_version`, `version_index.sequence_no` |
| `MutationBatch` | Ordered tuple `mutations` |
| `VersionEnd` | `fdb_version`, `total_mutations`, `bridge_timestamp_ns` |

The sink's `batch_index` is the mutation's position in its Kafka record, not an upstream field. `param1` is the key or clear-range start; `param2` is the value or range end. The sink strips the configured prefix from keys.

The listener copies native `version_group.version` into the wire version. **Equality with `get_committed_version()` passed on the live Compose stack.** `make spike` verified exact key/value bytes, the client's commit version, and receipt of a covering VersionEnd using the bridge's own deserializer.
